# Architecture and security boundaries

This is an experimental source snapshot, not a security certification or a supported install.

- **Profiles:** ProfileStore/RdpProfile validate imports and launches with a narrow classified settings/value allowlist, including the supported public EU example family. Only BOM-less UTF-8 or BOM-marked UTF-16LE is accepted. Unknown/secret-bearing/unclassified fields, signatures, enabled KDC proxy and unsupported variants are rejected. Accepted bytes are preserved in private app-owned storage; rejected saved files are not rewritten/deleted. Do not strip fields or bypass validation. Current live portal compatibility is unverified.
- **Session:** stock FreeRDP is driven over a private PTY with bounded prompts, asynchronous probes and owned-process lifecycle handling. Every transport requires exact 3.32.1/SSO-OFF self-reports and explicit console callbacks. Authorization requires state/S256; typed generation binding rejects stale replies. Canonical code+state submission is bounded to 4095 bytes. FreeRDP owns the PKCE verifier and token exchange, not the app.
- **BrowserAuth:** Chromium uses anonymous CDP pipes, not a debug TCP port. App automation is confined to the owned main frame and supported Microsoft origin/path; portal acquisition is an observed legacy-portal workaround, not a supported discovery API. One selected download is armed; acquisition only imports. Unsupported layouts can require administrator-supplied manual import.
- **Temporary sign-in storage:** browser profile/cache/temp require descriptor-checked ownership, 0700 permissions and tmpfs, without disk fallback. Chromium's automation flag disables the examined password-saving/filling gate and can affect site compatibility. Cookies survive consecutive sign-in-window handoffs within the browser lifetime. Normal shutdown removes the private browser profile. Swap and abnormal-exit leftovers remain limits; no guarantee covers all credential APIs, outside-tree writes or every descendant schedule.
- **Certificates:** recognized certificate-trust requests terminate the connection without a Qt probe, consent UI, fingerprint exception, trust answer, `/cert:ignore` or certificate-triggered restart. Explicit user Reconnect is separate. Ordinary upstream policy/stores/caches can accept before prompting; this is not universal endpoint binding or chain-only trust confinement. Legitimate connections requiring old exceptions may fail; ask the administrator to review server identity/trust, never weaken verification as a workaround.
- **Redirection:** drive/home, raw USB, smartcard, printer, serial/parallel, SSH-agent and audio forwarding are not enabled app features; clipboard file transfer is off. The selected offline candidate has camera client OFF and bounded downstream source evidence, not a universal guarantee for every artifact reporting 3.32.1/SSO-OFF. File-transfer-off does not exclude temporary/FUSE initialization or all file-related writes. Local WebAuthn security keys are distinct from raw USB forwarding; phone passkeys are not supported inside the remote session.
- **UI:** launcher follows desktop Qt scaling/backend (including native Wayland). FreeRDP owns its separate X11/XWayland desktop. Dynamic remote resolution depends on server support; current live resize/input/PIN-focus acceptance and multi-monitor behavior are not established. The PIN field clears on focus loss; Enter submits once, and cancellation disconnects. No automatic PIN retry occurs.
- **Local trust:** 0700/0600 permissions do not isolate hostile same-user software. Dump restrictions and memory clearing are best effort, not cryptographic erasure. Qt, Chromium, FreeRDP, system libraries and the OS are trusted dependencies. No telemetry or app token cache is added.

Use synthetic fixtures for development; no credentials, real profiles, trust-store mutations, real-session capture or hardware retry consumption without explicit coordination. See [verification limits](VERIFICATION.md).
