# Architecture and security boundaries

How OMAWIN365 is built, and the rules it enforces. "Must" items are invariants with tests behind them.

- **Explicit connection only.** Importing or downloading a connection file never connects. A connection starts only when you press Connect (or Enter on a profile); FreeRDP's auto-reconnect is off.
- **Connection files** (`ProfileStore`, `RdpProfile`). Imports and every launch are checked against a strict allowlist of settings and value formats. Unknown, credential-bearing or unclassified settings are rejected rather than stripped, and hostnames must be DNS names (no IP literals in any form). Files must be BOM-less UTF-8 or BOM-marked UTF-16LE. Signature fields are kept unchanged but not verified. Accepted bytes are stored privately (0600) and never rewritten.
- **FreeRDP session** (`Session`, `PromptParser`). FreeRDP runs in a private terminal; its prompts are parsed with fixed limits. The app requires FreeRDP 3.32.1 with SSO MIB off, forces console sign-in callbacks, and requires OAuth state plus PKCE (S256). Stale replies from an earlier attempt are rejected. A PIN is sent once, only to a waiting PIN prompt; cancelling disconnects and never retries.
- **Certificates.** FreeRDP verifies every certificate against the system CA store and the expected hostname. The app never answers a certificate-trust prompt, sends `/cert:ignore` or adds an exception: if FreeRDP asks, the connection stops. The private FreeRDP build carries one patch so that wildcard gateway certificates match (see the [README](../README.md)).
- **Local redirection.** Drive/home, raw USB, smart card, printer, serial/parallel, SSH agent and audio forwarding are off; clipboard file transfer is off. Your security key works through in-session WebAuthn redirection, not raw USB. Phone passkeys don't work inside the session.
- **Sign-in browser** (`BrowserAuth`). Chromium is driven over anonymous DevTools pipes, not a network port. Automation runs only in the owned main frame of `https://client.wvd.microsoft.com`, and a connection-file download is accepted only from that origin. The profile, cache and temp directories must be private (0700) tmpfs; password saving is off, and crash data stays in the private directory. Chromium's background services (push messaging, component and model downloads, network time) are blocked by host resolver rules. The window closes when the desktop connects; closing it earlier cancels the connection.
- **Processes.** FreeRDP and Chromium run in their own process groups and are killed and reaped on exit. Signals are only ever sent to a process group the app still owns: the app never signals a recycled PID.
- **Cleanup.** Normal exit removes the private browser profile and FreeRDP's temporary config. After a crash or kill, leftovers stay in your memory-backed runtime directory until logout; swap is not covered.
- **Out of scope.** Another process running as the same user can already read 0600 files or swap them between check and use. Qt, Chromium, FreeRDP and the OS are trusted dependencies. There is no telemetry and no app token cache.
