# Architecture and security boundaries

How OMAWIN365 is built, and the rules it enforces. "Must" items are invariants with tests behind them.

- **Explicit connection only.** Importing or downloading a connection file never connects. A connection starts only when you press Connect (or Enter on a profile); FreeRDP's auto-reconnect is off.
- **Connection files** (`ProfileStore`, `RdpProfile`). Imports and every launch are checked against a strict allowlist of settings and value formats. Unknown, credential-bearing or unclassified settings are rejected rather than stripped, and hostnames must be DNS names (no IP literals in any form). The gateway and server addresses in the file must be in Microsoft's `.wvd.microsoft.com` or `.wvd.azure.us` zones, because FreeRDP sends the Windows 365 access token to the gateway the file names. Files must be BOM-less UTF-8 or BOM-marked UTF-16LE. Signature fields are kept unchanged but not verified. Accepted bytes are stored privately (0600) and never rewritten.
- **FreeRDP session** (`Session`, `PromptParser`). FreeRDP runs in a private terminal; its prompts are parsed with fixed limits. The app requires FreeRDP 3.32.2 with SSO MIB off, forces console sign-in callbacks, and requires OAuth state plus PKCE (S256). Stale replies from an earlier attempt are rejected. A PIN is sent once, only to a waiting PIN prompt; cancelling disconnects and never retries.
- **Certificates.** FreeRDP verifies every certificate against the system CA store and the expected hostname. The app never answers a certificate-trust prompt, sends `/cert:ignore` or adds an exception: if FreeRDP asks, the connection stops. FreeRDP builds without uriparser, Arch's included, match wildcard gateway certificates only from 3.32.2 on (see the [README](../README.md)).
- **Local redirection.** Audio playback, microphone forwarding and clipboard sharing are per-PC choices: audio and microphone are off until enabled, clipboard is on until disabled (text, images and HTML, never files). Choices are saved in local metadata, never in the connection file, and are captured when a session starts; a change during a session applies only on Reconnect, and the launcher says so. Display scale is app-wide. Drive/home, raw USB, smart card, printer, serial/parallel and SSH agent forwarding are off; clipboard file transfer is off. Your security key works through in-session WebAuthn redirection, not raw USB. Phone passkeys don't work inside the session.
- **Sign-in browser** (`BrowserAuth`). Chromium is driven over anonymous DevTools pipes, not a network port. Automation runs only in the owned main frame of `https://client.wvd.microsoft.com`, and a connection-file download is accepted only from that origin. The profile, cache and temp directories must be private (0700) tmpfs; password saving is off, and crash data stays in the private directory. Chromium's background services (push messaging, component and model downloads, network time) are blocked by host resolver rules. The window closes when the desktop connects; closing it earlier cancels the connection.
- **Remembered sign-in** (`SignInCache`). Off by default, app-wide, and changeable only while disconnected. Only secure cookies for the exact `login.microsoftonline.com` host are kept, with their own attributes and expiry; other domains, partitioned cookies, passwords, PINs, OAuth tokens and browser storage never are. Cookies are captured only after a validated OAuth callback or a completed portal download, and restored over the DevTools pipe before the first page loads. **Until the app closes** holds them in memory only. **On this device** also saves the unexpired persistent ones (never session cookies) as one Secret Service item, through serial, cancellable calls off the UI thread with a 15-second timeout and no plaintext fallback. Forget, Off, or leaving the keyring choice deletes that item after any save already running, and a load that overlaps the deletion returns nothing. A failed deletion is reported, and Forget stays offered, across restarts too, until the keyring confirms it. Optional cookie calls time out quickly and never block sign-in. An unlocked keyring is not a boundary against your own processes.
- **Processes.** FreeRDP and Chromium run in their own process groups and are killed and reaped on exit. Signals are only ever sent to a process group the app still owns: the app never signals a recycled PID.
- **Cleanup.** Normal exit removes the private browser profile and FreeRDP's temporary config. If the app itself crashes or is killed, the browser profile stays in the tmpfs `$XDG_RUNTIME_DIR` until that directory is removed, normally at your last logout, and FreeRDP's config stays under `$TMPDIR` or `/tmp` until the system or you clear it (`/tmp` is tmpfs on Arch by default; a disk-backed `$TMPDIR` can survive reboot). Swap is not covered.
- **Out of scope.** Another process running as the same user can already read 0600 files or swap them between check and use. Qt, Chromium, FreeRDP and the OS are trusted dependencies. There is no telemetry and no app token cache; remembered sign-in keeps Microsoft's sign-in cookies, not tokens.
